DoL8 reads Linux CPU energy counters before and after a workload, then reports a high-resolution estimate of energy, power, and thermal context.

Think of RAPL as an electricity meter inside the processor. DoL8 takes a starting reading, runs one target at a time, takes another reading, and calculates the counter delta in joules. Temperature and statistical variation add context to that number.

Why it matters

Energy should be visible during development.

Runtime is only one dimension of software cost. Energy use affects heat, battery life, cloud spend, and the efficiency of systems under sustained load.

DoL8 gives developers a repeatable starting point for comparing workloads. Its output is an estimate with explicit limits, not a substitute for calibrated lab equipment or a whole-system power meter.

  • Speed is not energy. Two programs with identical runtime can differ up to 30x in energy consumed. Time was always visible; energy never was.
  • Silent throttling. An overheated CPU slows itself down with no error and no log, hiding a cause of mysterious performance loss.
  • Heat shortens hardware life. Roughly every sustained +10 C can halve component lifetime. Software slowly consumes the machine it runs on.
  • Waste is money. Cloud billing converts directly to compute time. Measured energy shows which workloads to optimize first.

FAQ

Questions, answered

Does it work on Windows or macOS?

No. RAPL is exposed by the Linux kernel only. v1.0 targets Linux bare metal; other platforms are on the roadmap.

Does it work in a VM or WSL2?

No. Virtualized hardware hides RAPL. That is a physical limitation, not a bug.

Is the measurement exact?

No honest tool can claim that. RAPL counters are quantized. DoL8 reports high-resolution estimates with explicit margins.

Can it isolate one process from everything else running?

RAPL meters the whole CPU socket. DoL8 runs targets sequentially for clean attribution; watch mode reports an app share clearly labeled ESTIMATED.

Does the tool itself distort measurements?

DoL8 spends much of each run waiting on measurements, but overhead still exists. Measure it with a no-op workload; no bare-metal overhead number is published yet.

Can it measure GPU energy?

This build can sample NVIDIA GPUs when optional pynvml support is available. Other GPU vendors are not supported; broader GPU support matters most for gaming and ML workloads.

01 / Concept

RAPL as a counter delta

Linux powercap exposes cumulative energy counters in microjoules. DoL8 records a start value, runs one target, then records an end value. The energy delta is converted to joules; average power is energy divided by elapsed time.

If a counter rolls over, DoL8 uses that domain's max_energy_range_uj to correct one wrap. Package counters are preferred for total energy to avoid adding nested package, core, and DRAM domains together; individual domains remain available in reports.

02 / Architecture

Small modules, explicit boundaries

dol8/ rapl.py discover domains, read counters, correct wraps thermal.py optional temperature and battery sensors poller.py 100ms samples, peaks, frequency and optional GPU runner.py target process, timeout, containment, PowerProfiler stats.py idle baseline, aggregation, confidence, A/B verdict report.py terminal, JSON, CSV and estimate labels compare.py sequential scans and alternating A/B runs watch.py machine observation and ESTIMATED CPU-time share gate.py CI baseline gate and boot-energy calculation cli.py run / compare / watch / boot-energy / doctor / gate doctor.py environment checks for RAPL and optional sensors

Optional thermal, battery, frequency, and NVIDIA GPU data degrade gracefully when unavailable. RAPL is required for energy profiling.

04 / CLI

Command reference

dol8 run TARGET [TARGET ...]

Measure one or more scripts sequentially. Directories are invoked as pytest targets.

dol8 run train.py --runs 5 --warmup 1 --json run.json --csv timeline.csv
--timeout 600 --price 0.15 --runs-per-day 20 --grid-factor 0.45
--gate-baseline baseline.json --threshold 15
--no-warmup

--runs defaults to 1; use multiple runs to estimate variation. Warm-up defaults to 1 and is discarded.

dol8 compare A.py B.py

Run alternating target order, with a fresh baseline and discarded warm-up for each observation; compare means and noise.

dol8 compare before.py after.py --runs 5 --timeout 600
--price 0.15 --grid-factor 0.45 --json compare.json

dol8 watch

Observe machine energy; process energy is CPU-time prorated and always labeled ESTIMATED.

dol8 watch --attach 1234 --out session.json
# Omit --attach for automatic process selection

dol8 boot-energy

Estimate energy since boot from current counters and uptime. Long uptimes can exceed the counter wrap window.

dol8 boot-energy --json boot.json

dol8 doctor

Check RAPL availability, counter movement, wrap math, sensors, timer, and output-directory access. Exit 0 when ready and 1 when required checks fail.

python -m dol8.cli doctor --output-dir .

dol8 gate save

Create a CI baseline from a prior result.

dol8 gate save result.json --out baseline.json

07 / Statistics

Baseline, warm-up, repeats

  1. For each target, measure an idle baseline (5 seconds in the CLI orchestration).
  2. Run the configured warm-up and discard its measurements.
  3. Run measured samples sequentially. Set --runs 5 for a useful initial comparison.
  4. Subtract estimated idle energy and floor results at zero.
  5. Report arithmetic mean, sample standard deviation, and coefficient of variation. HIGH is below 5%, MEDIUM below 15%, otherwise LOW. A one-run sample is LOW because variation is unknown.
  6. A/B differences are significant only when both groups have at least two samples and the mean delta exceeds twice the combined standard deviation; otherwise the verdict is INCONCLUSIVE.

08 / Honesty

Constraints and attribution

  • Energy profiling requires Linux bare metal with readable RAPL counters under /sys/class/powercap. VMs and WSL2 are unsupported when they hide those counters.
  • Every reading is a high-resolution estimate, never an exact process-level energy measurement.
  • Targets execute one at a time; scan and compare do not run targets in parallel.
  • Watch mode measures machine energy. Its per-process share is CPU-time prorated and labeled ESTIMATED.
  • Temperature, battery, CPU frequency, DRAM domain, and GPU telemetry are optional and may be unavailable.
  • No bare-metal Linux validation values are published yet. See the project validation record before relying on hardware plausibility.

Linux bare metal / first measurement

Install DoL8

DoL8 reads Linux powercap counters. Install it on a supported bare-metal Linux system and run the doctor before profiling.

Hardware requirement: Linux Mint or Ubuntu, Intel or AMD CPU with RAPL exposed through powercap, and Python 3.9+. Virtual machines and WSL2 are NOT supported if RAPL is hidden.

  1. Install system prerequisites

    Python, venv support, pip, and Git are required.

    sudo apt update
sudo apt install -y git python3 python3-venv python3-pip

  2. Clone the repository

    Replace the organization in the URL with the actual repository owner.

    git clone https://github.com/YOUR-ORG/DoL8.git
cd DoL8

  3. Create and activate a virtual environment

    python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip

  4. Install DoL8

    python -m pip install -e .

  5. Check this machine

    Doctor reports readable RAPL, counter movement, wrap math, sensor availability, timing, and output access.

    python -m dol8.cli doctor

  6. Fix RAPL permissions if needed

    Only apply a udev rule if the doctor reports permission denied. Review your local security policy before making powercap counters world-readable.

    sudo bash -c 'echo SUBSYSTEM=="powercap",MODE="0666" > /etc/udev/rules.d/99-rapl.rules'
sudo udevadm control --reload
sudo udevadm trigger

  7. Run a first target

    Use your own script or one of the project fixtures. Example values depend on hardware and workload.

    dol8 run workload.py --runs 5 --json result.json

Verify the counter

Confirm that energy moves

On supported Linux hardware, read the counter twice several seconds apart. The number is cumulative microjoules and should advance while the machine is active.

cat /sys/class/powercap/intel-rapl:0/energy_uj
sleep 5
cat /sys/class/powercap/intel-rapl:0/energy_uj
python -m dol8.cli doctor

Some systems expose a differently named package path. DoL8 discovers domains dynamically; this manual probe path is illustrative.

Troubleshooting

Common setup issues

RAPL is missing or unreadable

Confirm this is bare-metal Linux and inspect /sys/class/powercap. If the path exists but reads return permission denied, apply the udev permission steps above and rerun python -m dol8.cli doctor. A VM or WSL2 may not expose the hardware counters.

No DRAM domain is listed

DRAM energy is not exposed on every CPU. DoL8 skips missing domains and continues with the domains the kernel provides.

Temperature or battery is unavailable

Sensor availability depends on the system and psutil support. Missing thermal or battery readings are optional and do not invalidate the RAPL energy measurement.

Doctor says the counter did not move

Check that the selected counter is readable, wait longer, and repeat while running a modest workload. A frozen or inaccessible counter means DoL8 cannot provide a useful energy estimate.
